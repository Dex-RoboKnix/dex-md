# DEX838

## For a person

DEX838 is a short way to write down a request so that it cannot be misread. It has a fixed shape:

```
dex(scope, @context)["subject"]
```

- **scope** is the kind of job, one word: what may be touched.
- **@context** is what is known: where the job sits, the issue, the source.
- **"subject"** is the thing you want.

Two kinds of bracket inside the subject carry meaning:

- `dex()` is **softcode**: your intent. "Make this clearer."
- `dex[]` is **hardcode**: a literal rule that must hold. "Must keep the 2024 figures."

Why it matters. A loose request leaves the model to guess what is a wish and what is a rule. DEX838 separates the two, and a person can read it too, so you can check what was asked.

You rarely write DEX838 by hand. In a Dex vault, every note, held question, late answer and reminder opens with one DEX838 line, and the engine checks it before acting on it. A line that does not parse is not acted on: it waits for you.

```
dex(dex-loop, @source:github,issue:115,comment:6900000001,resumes:dex-loop-115)["Agree, go to phase 4"]
```
Readable: a late answer. The owner commented on issue 115; the line says which held question it answers, and the subject is the first line of the comment.

DEX838 is part of DexSpine (L1). The standard and its reference parser are public in [dexspine-core](https://github.com/Dex-RoboKnix/dexspine-core). Pre-1.0.

## For an LLM

- Grammar: `dex(<scope>, @<context>)["<subject>"]`. The reference parser is `src/dex838.js` in dexspine-core (`parseDEX838(line, { strict: true })`).
- In a vault, the same parser is an engine module: `node dex-vault/.dex/vault.mjs run p6/dex838-parse --json '{"line":"..."}'`. It is built from a pinned dexspine-core commit, so it works offline.
- Softcode `dex(...)` is intent. Hardcode `dex[...]` is a literal requirement. Treat them differently: hardcode is never softened, rewritten or dropped.
- A hardcode qualifier may contain nested brackets, for example `dex[must satisfy X [clause 4]]`. Match by bracket depth, not by the first `]`.
- A context value may contain a colon (a URL). Keys are unique.
- Strict mode rejects what lenient mode would repair: an empty context item, a stray `@`, a duplicate or empty key, an unterminated `dex(` or `dex[`. Use strict mode before acting on a line; a line that fails is not acted on.
- Do not invent a scope or context the human did not give. If one is missing, ask.
- Never apply a hardcode as `VERIFIED` yourself. Only the human verifies.
