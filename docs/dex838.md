# DEX838

## For a person

DEX838 is a short way to write down a request so that it cannot be misread. It has a fixed shape:

```
dex(scope, @context)["subject"]
```

- **scope** is the kind of job (one word).
- **@context** is where the job sits.
- **"subject"** is the thing you want.

Two kinds of bracket carry meaning:

- `dex()` is **softcode**: your intent. "Make this clearer."
- `dex[]` is **hardcode**: a literal rule that must hold. "Must keep the 2024 figures."

Why it matters. A loose request leaves the model to guess what is a wish and what is a rule. DEX838 separates the two. A person can read it too, so you can check what you asked for.

You rarely write DEX838 by hand. Dex uses it behind the scenes. The `838-scrape` skill turns a free-text task into a DEX838 string before work starts.

DEX838 is part of DexSpine (L1). The standard is public in `dexspine-core`. Pre-1.0.

## For an LLM

- Grammar: `dex(<scope>, @<context>)["<subject>"]`. The outer shape is checked by `DEX838_REGEX` in `packages/dexspine-core/src/dex838.js`.
- Softcode `dex(...)` is intent. Hardcode `dex[...]` is a literal requirement. Treat them differently: hardcode is never softened, rewritten or dropped.
- A hardcode qualifier may contain nested brackets, for example `dex[must satisfy X [clause 4]]`. Match by bracket depth, not by the first `]`.
- A context value may contain a colon.
- Strict mode rejects malformed input (such as an unterminated `dex[`). Prefer strict when you build a string yourself.
- Do not invent a scope or context the human did not give. If one is missing, ask.
- Reference: the canonical grammar and parser are in `dexspine-core` (ADR-0013 section 5). Read them there; do not copy them into a vault.
- In a Dex run, never apply a hardcode as `VERIFIED` yourself. Only the human verifies.
