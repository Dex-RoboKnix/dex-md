# Use case 3: An AI chat-export database

**Profile.** A person has exported their conversations with AI assistants into a folder of JSON and a small database. They want to find what they decided, learned and left unfinished.

**Folder kind.** Blank-with-context: exports and a database file, no project code.

## Why-ladder (illustrative answers)

| Rung | Answer |
|---|---|
| 6 Pattern | "I keep re-asking questions I know I already worked out in a chat." |
| 5 Procedure | "Turn two years of chats into something I can search and trust." |
| 4 Process | "I lose decisions between sessions." |
| 3 Policy | "Anything I decided must be traceable to a chat." |
| 2 Principles | "My words stay mine; the model's reading is labelled." |
| 1 Values | "Not repeating myself." |

## Slant

Research and synthesis desk. Evidence: notes, open questions, many sources. Wrong if the real aim is deleting the data. The lens reads Scope as "which chats count".

## Sort and first grill angles

Stage 3 first sorts anything from an older version or another system (keep, where, archive). Then `dex-grill` works the gaps through the inventory, timeline, stall and done angles (method section 5).

## Privacy notes

- Chats are the most private material in this set. The vault stays local or in a private repo, never shared.
- Dex quotes only what a node needs. Chat contents never go into public docs, issues or this repo.
- Secrets pasted into chats are listed as a finding, never repeated.
- Third parties named in chats become role labels.

## What done looks like

An inventory of chats by topic, a timeline of decisions with source IDs, a list of unfinished threads, and a folio that links back to each source. The owner has confirmed the slant.
